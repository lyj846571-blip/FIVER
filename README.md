# Math Tool Router

This repository contains the public implementation of a step-level router for mathematical reasoning agents. The router selects a verifier backend for each critical reasoning step, using a learned model that estimates both correctness probability and verification cost.

## What is included

- `math_router/reason.py`: routerized reasoning loop with tool calls.
- `math_router/router_nnmodel.py`: improved 2PL correctness model plus cost predictor.
- `math_router/router.py`: checkpoint loading, embedding, and backend selection.
- `math_router/training/`: router JSONL loading, embedding, training, and evaluation utilities.
- `math_router/verifiers/`: Lean4-memory and DeepSeek dual-view verifier backends.
- `train_router.py`: CLI for training a router checkpoint from tool-evaluation JSONL.
- `run_problem.py`: CLI for a single problem or JSONL dataset.
- `prompts/`: all prompts used by the workflow and verifier adapters.

Router checkpoints are written under `router_models/` by default. The directory is generated automatically by `train_router.py` when `--output-checkpoint` points there, so a fresh clone can train the router without shipping model weights.

## Install

```bash
pip install -r requirements.txt
```

## Train the Router

Training data is JSONL in the router-evaluation format used by this project. Each line is one verifier result for one reasoning step and one tool. Rows with the same `sid` are grouped into one router sample.

Required fields:

```json
{"sid":"problem_1__turn0__step0","question_id":"problem_1","tool_name":"lean4","problem":"...","step_text":"...","gold_status":"CORRECT","pred_status":"CORRECT","success":1,"latency_s":12.3}
```

The router input is `step_text`. `success` trains the correctness head, and `latency_s` trains the cost head.

```bash
python train_router.py \
  --train-jsonl data/router_training/step_verdict_grouped_final_complete__regraded.jsonl \
  --output-checkpoint router_models/router_model_retrained.pt \
  --tool-names lean4,deepseek \
  --val-ratio 0.15 \
  --device auto \
  --embedding-base-url "$ROUTER_EMBEDDING_BASE_URL" \
  --embedding-api-key-env ROUTER_EMBEDDING_API_KEY \
  --embedding-model "$ROUTER_EMBEDDING_MODEL" \
  --specialty-dim 8 \
  --cost-hidden-dim 64 \
  --router-difficulty-epsilon "$ROUTER_DIFFICULTY_EPSILON" \
  --epochs 40 \
  --success-lr 0.01 \
  --cost-lr 0.01 \
  --batch-size 16 \
  --weight-performance 0.8
```

The repository includes the released router training JSONL files. Router checkpoints are generated by `train_router.py`; training choices are supplied as CLI arguments.

## Run a Single Problem

All model endpoints, model names, sampling parameters, retry counts, and seeds are supplied by the user at runtime.
The router embedding endpoint is separate from the memory-retrieval embedding endpoint: `--embedding-*` is used only by the router, while `--memory-embedding-*` is shared by Lean4 and DeepSeek memory retrieval.
The workflow always exposes the trained router over the `lean4` and `deepseek` backends. Pass both backend configurations explicitly.

```bash
python run_problem.py \
  --problem "Convert the point $(0,3)$ to polar coordinates." \
  --outer-base-url "$OUTER_BASE_URL" \
  --outer-api-key-env OUTER_API_KEY \
  --outer-model "$OUTER_MODEL" \
  --embedding-base-url "$ROUTER_EMBEDDING_BASE_URL" \
  --embedding-api-key-env ROUTER_EMBEDDING_API_KEY \
  --embedding-model "$ROUTER_EMBEDDING_MODEL" \
  --memory-embedding-base-url "$MEMORY_EMBEDDING_BASE_URL" \
  --memory-embedding-api-key-env MEMORY_EMBEDDING_API_KEY \
  --memory-embedding-model "$MEMORY_EMBEDDING_MODEL" \
  --router-model-path router_models/router_model_retrained.pt \
  --weight-performance 0.8 \
  --router-difficulty-epsilon "$ROUTER_DIFFICULTY_EPSILON" \
  --max-steps 50 \
  --memory-top-k 3 \
  --deepseek-verifier-attempts 1 \
  --deepseek-base-url "$DEEPSEEK_BASE_URL" \
  --deepseek-api-key-env DEEPSEEK_API_KEY \
  --deepseek-model "$DEEPSEEK_MODEL" \
  --lean-formalizer-base-url "$LEAN_FORMALIZER_BASE_URL" \
  --lean-formalizer-api-key-env LEAN_FORMALIZER_API_KEY \
  --lean-formalizer-model "$LEAN_FORMALIZER_MODEL" \
  --lean-backtranslate-base-url "$LEAN_BACKTRANSLATE_BASE_URL" \
  --lean-backtranslate-api-key-env LEAN_BACKTRANSLATE_API_KEY \
  --lean-backtranslate-model "$LEAN_BACKTRANSLATE_MODEL" \
  --lean-prover-base-url "$LEAN_PROVER_BASE_URL" \
  --lean-prover-api-key-env LEAN_PROVER_API_KEY \
  --lean-prover-model "$LEAN_PROVER_MODEL" \
  --lean-repl "$LEAN_REPL" \
  --lean-lake-path "$LEAN_LAKE_PATH" \
  --lean-project-root "$LEAN_PROJECT_ROOT" \
  --lean-repl-timeout-s 300 \
  --lean-translator-attempts 4 \
  --lean-prover-attempts 4 \
  --lean-inner-memory-top-k 2 \
  --lean-outer-memory-top-k 1
```

Add optional generation settings such as `--outer-temperature`, `--outer-top-p`, or `--seed` only when needed.

## Run a JSONL Dataset

```bash
python run_problem.py \
  --input-jsonl data/problems.jsonl \
  --problem-key problem \
  --answer-key answer \
  --output-jsonl outputs/results.jsonl \
  [the runtime arguments above]
```

## Notes

The code uses OpenAI-compatible HTTP APIs but does not contain API keys, private URLs, local filesystem paths, or fixed experiment seeds. Prompt text is stored in `prompts/` so it can be audited and modified independently from the code.
